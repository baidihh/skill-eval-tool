# Skill 评测工具技术方案

版本：v0.2（开发前修订稿）  
日期：2026-11-04  
依据：同目录《需求文档.md》v0.2  
状态：技术设计，尚未实施或完成平台联调

本版已合入技术方案 v0.1 的五项评审意见，明确固定报告快照、统一修订事务、执行与传输重试、备份恢复及对比规范化。v0.1 原文保存在“历史/技术方案-v0.1.md”，评审报告保留为历史记录。本版为设计约束，不代表已经完成实现或验证。

## 1. 设计基线

首期为单人、本机网页工具，完成一个真实 Skill 的新旧版本回归。采用检查项判定与 baseline-v1 门禁，不实现综合评分。在线调用、离线导入和演示来源永久区分。第一次预定尝试决定默认主样本，重试不覆盖原始表现；重评、复核和迟到结果采纳均通过新增记录及报告修订实现。

本文选择的技术栈属于实施建议。公司平台 API、裁判服务范围和测试环境尚待核实；本文中的平台接口均为本工具内部契约，不代表公司已有对应 API。开发时应锁定依赖版本，按官方文档确认实际调用方式，依赖锁文件随代码提交。

## 2. 技术选型与部署

| 部分 | 首期选择 | 原因 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite，Ant Design | 适合表格、表单、报告和证据查看；使用类型契约约束状态显示 |
| API | Python + FastAPI + Pydantic | 统一输入校验、JSON Schema 和 OpenAPI；方便实现结构化规则核验 |
| 持久化 | SQLite + SQLAlchemy + Alembic | 单机小规模无需独立数据库服务，具备事务与迁移机制 |
| 后台执行 | 独立 Python worker，数据库任务表 | 执行不依赖 HTTP 请求生命周期，避免首期引入额外队列服务 |
| 文件 | 本地不可变内容存储，SHA-256 寻址 | 固定 Skill、政策与证据内容，避免临时下载链接失效 |
| 平台及裁判调用 | 服务端适配层 + HTTP 客户端 | 隔离未知平台接口，凭证不进入浏览器 |
| 更新进度 | 前端按游标轮询事件与计数 | 单实验规模足够使用，刷新可恢复，不依赖长连接 |

Node 全栈也可实现，但本工具的主要后端逻辑是任务编排、资料解析及规则核验，选择 Python 更便于集中维护。首期不引入 Redis、Celery、对象存储服务或向量库；多人阶段再按实际需要迁移。

启动器同时启动 API 和 worker，API 提供前端构建产物。默认仅监听 127.0.0.1；使用固定本机 Origin 白名单、Host 校验和会话令牌，写请求校验 CSRF。拒绝任意跨域访问，静态 HTML 导出无需登录但不承载执行能力。worker 单实例锁控制执行权，异常退出后由启动器重启。配置和数据目录通过启动参数指定。

```text
浏览器 → 本机 API → SQLite（版本、任务、结果、修订）
                 → 本地文件存储（快照、附件、证据）
后台 worker → 专家适配器 → 公司测试专家平台
            → 规则引擎 / 裁判适配器 → 允许的评分服务
```

```text

backend/app/api/          HTTP 路由、请求校验和错误映射
backend/app/domain/       门禁、有效判分、对比和版本规则
backend/app/services/     发布、实验、复核、导入导出编排

backend/app/evaluators/   可信内置规则与结构化裁判
backend/app/storage/      数据模型、迁移、文件存储
backend/app/worker/       任务领取、执行、恢复、限额
schemas/                 交换包 JSON Schema
fixtures/                版本化退款验收包和预期结果
docs/                    接口文档、运行说明、验收记录
```

门禁和统计只在后端领域模块计算，前端展示服务端结果，不各自复制计算逻辑。报告和导出共同读取一个固定报告修订，避免页面、明细与下载结果不一致。

## 4. 数据模型与不可变性

所有对象使用独立 UUID 标识；UTC 保存系统事件时间，业务评测时间同时保留时区。结构化内容按固定规范序列化再计算 SHA-256，规范版本纳入哈希。未知字段保存 null，不能使用零或空字符串冒充已知值。

| 表/对象 | 关键字段及关系 |
| --- | --- |
| skill / skill_version | 名称、前版本、包清单、文件哈希、可信度 |
| expert_snapshot | 专家 ID、模型、参数、提示词、全部 Skill、工具、环境、配置版本、未知字段及核验依据 |
| dataset_draft / dataset_version | 可变草稿与发布集合分离；发布集合关联题目版本 |
| case_version | case_id、内容哈希、输入、执行资料、裁判资料、参考、检查项、固定评测时间、初始状态和用途 |
| evaluator_version / policy_version | 规则配置、输入要求、裁判模板与模型、适用性、关键性、门禁版本 |
| connection | 能力声明、允许服务范围、credential_ref；不存明文凭证 |
| experiment | 来源、环境模式、目的、冻结 manifest、状态、上限、关联基线、初次终态 |
| experiment_case | 固定题目版本、主尝试位置；唯一键为实验+题目版本 |
| execution_attempt | 尝试序号、执行状态、提交幂等键、外部运行 ID、请求快照、错误、时间、是否重试；区分逻辑执行与传输 |
| evidence / evidence_binding | 内容对象、来源、类型、解析状态、权限用途；绑定实验、题目及尝试 |
| grading_run / check_result | 确定尝试、评估器版本、错误状态、逐检查结论、理由及引用 |
| review_event | 原判/前有效结果、动作、结论、证据、理由、本地身份、时间 |
| report_revision | 前修订、有效结果选择清单、证据/配置观察版本、usage_record 选择清单、费用快照、覆盖率、汇总、生成原因和哈希 |
| provider_call / transport_request / usage_record | 逻辑调用、每次实际请求传输、追加消耗观察版本；预算预占、供应商去重键、币种、计价版本和覆盖范围 |
| job / event / receipt | 持久任务、追加事件、回调/导入幂等收据 |

发布版本、结果正文、原始判分、复核事件和报告修订采用追加写。状态迁移表可更新，但保存完整迁移事件；初次实验终态另列字段冻结。修订引用明确的判分和复核 ID，不依赖“取最新一条”。原始引用关系使用外键，启用外键约束；固定记录使用存储层更新保护。

文件写入先落临时目录并校验长度与哈希，再原子移动至对象目录，最后提交数据库引用。崩溃可能留下未引用对象，由恢复检查列出；不能清理仍被引用对象。发布评测集在单个数据库事务中完成，失败全部回滚。

## 5. 平台适配器契约

定义以下内部能力，由真实平台适配器映射到经确认的 API：

```text
capabilities() → 能力清单与限制
snapshot_expert(expert_id) → 配置快照及核验级别
prepare_case(case_context) → 测试环境/初始状态确认
submit(expert_id, execution_input, idempotency_key) → 外部调用标识或未知状态
lookup_by_key(idempotency_key) → 已提交/未提交/无法确认
poll(external_run_id) → 运行状态、最终回复及错误
collect(external_run_id) → 允许取得的产物、调用记录与消耗
cancel(external_run_id) → 已终止/已请求/不支持/未知
```

上述为本地方法语义，不是供应商 API 名称。能力清单逐项声明幂等、查询、取消、配置、产物、费用和触发信息。创建实验时，将检查项证据需求与能力匹配；必要前提不足则拒绝启动并返回具体原因。

适配器输入类型仅包含执行字段，没有 reference 和 judge_materials。附件分配独立执行目录和裁判目录；允许专家使用的工具检索范围不能覆盖裁判目录。保存脱敏实际提交请求以验证输入隔离。配置在提交前和结果回收时核对；缺失标未知，变化标漂移。

业务隔离由平台测试账号、工具权限、写入允许列表和初始状态恢复共同实现。本机目录隔离不等于远端业务隔离。无法验证测试边界时禁止有状态真实调用。平台不提供配置核验时允许符合条件的执行，但禁用严格 Skill 版本改善结论。

## 6. 执行、幂等与恢复

创建草稿时不调用专家。启动请求完成预校验后，在单个事务中冻结 manifest、预分配每题第一尝试、写入任务并返回实验 ID。客户端提交稳定操作键，刷新或重复点击返回同一操作结果。

worker 分别限制执行并发 1、评分并发 1，同时只允许一个实验执行。任务用短事务领取并设置租约、心跳和领取代次；写结果时校验代次。外部请求期间不持有数据库事务。SQLite 使用 WAL、短事务和忙等待超时；API 与 worker 的写冲突重试仅限本地事务。

提交外部任务前保存提交意图和幂等键。网络超时后，有外部 ID 则查询，有幂等查询能力则按键核对；无法确认时标 outcome_unknown，禁止自动重提。重启优先恢复查询，不根据任务租约到期直接重复提交。不能宣称分布式 exactly-once；依靠持久意图、平台幂等与未知状态防止盲目重发。

暂时性错误仅在确认未执行或平台保证幂等时允许重试 1 次；追加新尝试。业务失败不重试。每题第一次预定尝试保留主位置，即使未提交、取消或失败，也不自动换为重试成功。重评只消费固定证据，不发专家任务。

### 6.1 逻辑执行、传输与标识约束

上述“追加新尝试”只适用于真正重新执行专家任务。需求中的技术重试在界面可以统一展示，但存储和计量必须区分以下情况：

| 操作 | 标识与记录 | 统计影响 |
| --- | --- | --- |
| 同一次提交的安全传输重试 | 保留 attempt_id、provider_call_id、幂等键和请求哈希，新增 transport_request | 不产生第二次实际执行，不替换主尝试 |
| 查询恢复或幂等响应返回旧运行 | 将外部运行 ID 回附原尝试，追加查询/恢复事件 | 不新增执行、判分或重复账单 |
| 已确认原尝试未执行或已失败，且业务状态可安全重置后的重新执行 | 新 attempt_id、新提交键、新 provider_call_id，关联 retry_of_attempt_id | 保留首次失败，新结果只作恢复结果展示 |
| 对已有结果显式重评 | 新 grading_run 和裁判逻辑调用，引用原执行尝试 | 不发专家请求，评分费用另计 |

数据库唯一约束至少包括：experiment_case + attempt_seq；连接的供应商账号命名空间 + 提交幂等键；该命名空间 + external_run_id 的外部执行归属；provider_call + transport_seq。一个外部执行只能归属一个逻辑尝试；同键不同请求哈希拒绝，不能借复用键改输入。

适配器须声明供应商幂等键作用域、有效期及响应语义。键已过期或查询不能确认原请求时，不因“平台通常支持幂等”而重发。未知原执行必须先查询；供应商明确保证同键重传不会产生新执行且仍在有效期内时，才允许记录传输重试；否则进入 outcome_unknown。真实重新执行必须满足表中的确定终态/未执行及初始状态前提。

若原尝试已因超时进入终态，后续查询或同键重传取回原运行结果，按迟到结果追加与显式采纳处理，不能将其登记为第二次成功执行。单次技术恢复预算最多 1 次，传输重试与真正新增执行共享此预算，禁止在不同层级各自动重试一次；HTTP 客户端不额外隐式重试提交请求。只读轮询使用独立速率和截止时间。

### 6.2 裁判调用与消耗恢复

每个启用维度的初始裁判逻辑调用在事务中分配稳定 provider_call_id，冻结输入哈希并预占调用额度；发送前持久化 transport_request 和发送意图。每个实际发送请求均占传输额度，结果回写前崩溃也不能归还为未消耗。初始逻辑调用最多 6 个，各自技术重试最多 1 次；实际传输最多 12 次，未启用维度不分配额度。显式重评另建批次和上限，不重置原批次记录。

裁判服务有有效幂等/查询能力时恢复原逻辑调用；没有时，将旧传输结果及费用标为未知，只能在剩余重试额度内显式记录可能重复计费的新传输，不无限重发。预算按所有已发送及发送状态不明的请求保守占用。供应商 usage/账单按供应商事件或费用项去重；同一费用项的实收、估算和迟到修正以追加版本表达，新值替代旧观察参与汇总，不能相加制造重复费用。无法确认请求是否被接受或收费时保留缺失和上界，不把未知记零。

### 6.3 状态、取消与结果回收

执行、判分和实验状态严格遵循需求 §10。首次终态保留；后续恢复显示独立进度。取消事务设置停止标记，worker 每次提交前重新检查；已在途请求尽力取消并持续查询，最终保留未确认外部任务。取消不会回滚业务。迟到结果作为候选证据追加，显式采纳后才形成新报告修订。

首期不开放入站平台回调端口，优先使用出站轮询。轮询或结果消息用 receipt 唯一键和内容哈希去重；同键不同内容进入冲突记录。若平台仅支持回调而无本机可用的状态查询，需要另行确认获准中继方案，不能无认证公开本地服务。

## 7. 评分与证据校验

规则评估器注册固定类型：字段与类型、必需字段、精确值、数值容差、结构化业务规则。用户只配置参数，不上传执行代码。政策与参考存在冲突时产生 data_error，不作为 Skill 失败。

裁判输入包括固定标准、允许资料、确定尝试的输出和证据清单；被测内容明确作为数据封装。裁判无外部工具和代码执行能力。每个启用维度默认至多一次初始调用，每题最多 6 次；技术重试最多 1 次。显式重评单独确认与计量。

裁判输出经 Pydantic/JSON Schema 校验：check_id、pass/fail/insufficient_evidence/not_applicable、理由、evidence_refs、缺失项。服务端验证检查项归属、固定适用性和引用授权；文本行范围、JSON 路径、CSV 行列及调用 ID 必须存在。非法结构或引用产生 grading_error。引用存在不证明内容支持结论，仍需校准和人工复核。

证据存储状态区分 missing、acquired、parsed、parse_failed、truncated、unsupported。解析使用可信文本/JSON/CSV 解析器，保留原始内容与派生视图关系。影响判断的截断、失败和缺失不能判通过。裁判输出引用固定证据快照；行号是解码后固定文本行号，JSON 使用明确路径约定，CSV 保存从 1 开始的数据行与列名定位。

人工通过也执行证据约束；关键模型检查未校准完成时设为人工必审或辅助，不得绕过门禁。校准集覆盖需求 §8.4 的五类样例，保存人工标签、裁判输出、分歧和对应版本。

## 8. 结论、复核与报告修订

检查聚合和题目结论逐项实现需求 §9；关键失败不能抵消，已存在有效必选失败时为 not_passed，并同时显示其他未完成项。无有效失败但仍缺必要判分或复核时为未判定；全部适用必选项有效通过且要求满足才为 passed。适用性在策略发布/实验创建时固定。

聚合保存固定分母 N，分别计算已判定覆盖率、完整判分覆盖率、全样本通过占比和已判定题通过率；零分母返回 null 并附原因。baseline-v1 有失败即不通过，无失败但不完整为未判定，全部满足才通过；配置漂移阻止通过。技术运行状态独立保存。

### 8.1 所有修订写入共用的事务协议

初次判分发布、复核/撤销、自动候选选择、迟到结果采纳、配置核验变更和消耗更新统一调用领域服务 append_report_revision，不允许 API 或 worker 直接替换 current_revision_id 或结果选择映射。

1. 人工操作携带 expected_revision_id 和稳定 operation_id；后台操作携带稳定事件 ID。同一操作重复处理返回既有结果；同键不同内容拒绝。
2. 短写事务内读取当前修订，验证人工预期及所有引用/证据要求，仅应用本次增量，保留其他题目和已有人工有效结果。原始调用、判分和账单可先独立持久化为候选，事务失败不得重新发外部请求。
3. 在同一事务追加复核事件（如有）、完整不可变修订与汇总，并以“当前指针仍等于读取值”为条件更新指针；影响行数须为 1。操作收据和通知事件一并提交。
4. 人工预期过期或条件更新失败时回滚并返回 409；后台冲突回滚，在有限的本地事务重试内读取新修订重新合并，不能用旧映射覆盖。耗尽重试则保留待处理任务，由 worker 恢复。

撤销复核也追加事件，恢复该检查明确的前有效结果，其他检查不回退。自动重评先作为候选，不覆盖人工结果；首次自动判分只填充尚无有效结果的相应项。复核日志标注本地未认证身份。证据内容与解析结果、配置核验结果均版本化，采纳新观察生成新修订，不原地改变旧修订引用的内容。

### 8.2 固定报告与实时运行视图

报告 API、HTML 导出和对比必须显式携带 revision_id。修订固定有效判分、人工复核、证据及解析版本、配置核验状态、观察截止事件、usage_record 的观察版本与计价依据、费用快照和覆盖范围。执行质量仍使用主尝试；消耗范围包含该修订观察时已经记录的全部执行和裁判尝试，已知费用、币种、估算与缺失分别展示，不混加不同币种。

后到费用、实收修正、额外重评、证据补全或配置核验不修改旧报告。由统一修订服务生成新修订并记录变更原因；旧修订的正文、金额、覆盖率、引用和内容哈希保持不变。单纯费用更新不改变有效判分，也不能作为执行质量改善。若资料被显式删除，旧修订显示不可用，不从其他版本替补正文。

实验运行页可另读实时接口显示当前队列、在途调用和“截至当前累计消耗”，须附观察时间并标明实时；实时字段不合入固定报告、HTML 或严格对比。导出与历史链接始终绑定指定修订，不能内部替换为最新修订。

## 9. 严格对比

后端比较 manifest，构造“除目标 Skill 版本之外”的条件指纹；数据集、政策、专家其他配置、模型、参数、工具、初始环境、裁判、策略、来源和尝试规则均参与检查。未知必要字段、漂移或仅人工外部登记返回 blocker，而非把 null 视为相同。

### 9.1 comparison_manifest-v1 规范化

对比使用独立的白名单投影，不直接删除原 manifest 的一个字段后哈希。保存投影版本、规范化对象、条件指纹及字段级差异，算法版本不同先按相同算法重新投影，不能直接比较不同算法的摘要。

| 字段组 | 纳入行为条件 | 排除或特殊处理 |
| --- | --- | --- |
| 任务 | 固定题目 ID/版本、输入及资料内容标识、权威政策、评测时刻、初始状态版本 | 排除草稿/快照内部 UUID 与抓取时间；不替换发生变化的题目内容 |
| 专家/模型 | 供应商、实际模型版本、有效生成参数、系统提示词内容、记忆设置 | 镜像专家 ID 和快照 UUID 不直接入指纹，保留为核验依据 |
| 技能 | 按明确目标 Skill 逻辑身份定位一个目标槽位，其他 Skill 的内容与加载顺序保持 | 目标槽位保留身份与调用模式，将其包版本/哈希替换为固定占位；不排除整个绑定列表 |
| 工具/环境 | 工具行为版本、权限范围、测试数据/环境内容、初始状态恢复语义、缓存策略 | 排除凭证值和 credential_ref；保留凭证代表的可访问范围，不因去掉秘密而忽略权限差异 |
| 判分/执行 | 评估器内容版本、评分策略、裁判模型/提示词/参数、来源、尝试选择和运行限制 | 判分记录/报告修订 UUID 不入条件指纹；人工复核与质量来源仍按下述独立门槛检查 |

平台配置版本用于检测每次运行内漂移。跨实验配置版本不同，仅在两边相关有效行为字段完整、已核验且规范化后相同时允许比较；若版本是唯一核验依据而内容不可取得，不忽略该变化，返回无法确认条件一致。目标 Skill 依赖文件变化属于目标包变化，但权威政策或执行资料的变化仍独立阻断严格对比。

对象键按固定顺序序列化；只有明确无序的集合可排序，技能加载顺序、消息和工具调用顺序不得擅自排序。数值按字段定义规范化，文本不删除有行为意义的空白。字段状态区分已知、合法不适用与未知；默认值只在供应商契约明确且已核实有效值时展开，不能把未知当默认。Schema 为必要行为字段声明核验要求；投影外出现尚未分类的行为扩展时返回 blocker，防止白名单静默漏掉新参数。

必要字段未知、目标槽位无法唯一确定或仅人工外部登记时，在哈希前返回 blocker；两个 null 不视为已确认相同。strict_eligible 同时取决于条件指纹、题目配对、配置可信度和复核口径，不能仅凭哈希相等判断。

### 9.2 配对与结论

题目按 case_id + case_version + 内容标识配对。对齐人工复核口径，只有一边复核时禁止严格改善。返回 strict_eligible、blockers、条件差异、配对覆盖和逐题变化。passed/not_passed 的转换决定改善与退化；技术失败或未判定属于不可比较。评分修订变化独立标记，不能呈现为执行能力提升。

首期文案限定“本次固定样本”。不同条件仍可描述性并排展示，但不产生严格版本改善结论。

## 10. API 设计与前端

使用 /api/v1，错误格式统一为 code、message、request_id、field_errors 和可重试标识；敏感供应商错误不直接返回。写入使用幂等操作键或版本修订前置条件。

| API 组 | 核心操作 |
| --- | --- |
| /objects、/skill-versions | 登记、快照、归档、依赖查看 |
| /datasets、/dataset-versions | 草稿编辑、发布校验、固定版本读取 |
| /imports | 上传、预览校验、确认提交；来源由服务端决定 |
| /experiments | 草稿、能力预检、启动、复制、列表 |
| /experiments/{id}/events | 游标查询事件与进度 |
| /attempts | 固定结果、允许的技术重试、迟到结果采纳 |
| /gradings | 重评、候选选择、检查明细 |
| /reviews | 确认、改判、撤销及冲突处理 |
| /reports/{id}/revisions/{revision} | 固定报告、证据与导出 |
| /comparisons | 两个固定报告修订的条件校验与逐题比较 |
| /connections、/settings | 能力、凭证状态、限额与用量 |

前端落实需求 §15 七组页面。来源标签、技术状态和门禁分别显示；未知不能渲染成成功或 0。草稿可编辑，历史只读。证据纯文本显示，HTML 转义；从证据返回保留筛选和滚动位置。API 返回分页及筛选字段，避免一次加载全部证据。具体请求体、状态码和完整 Schema 在《接口文档》中冻结。

## 11. 导入、导出与文件处理

交换包 manifest.json 使用 schema_version，至少定义对象版本、题目版本、附件清单和运行记录；附件声明用途、路径、大小与 SHA-256。运行记录含外部 ID、来源、尝试序号、时间、配置核验与原始结果。导入来源强制为 imported 或 demo，无法通过包字段创建 live。

先上传至隔离临时目录，验证 Schema、依赖、配额及所有文件，再生成预览。确认时重新核对文件哈希，在事务内提交。拒绝绝对路径、越级、符号链接、重复路径、加密包和非法目录；按流累计压缩与实际解压字节，限制压缩包本身及解压总量。相同幂等键同内容返回既有记录，内容冲突拒绝。

导出生成 JSON、转义后的静态 HTML 和可选证据 ZIP；排除凭证与未允许字段，清单注明修订及缺失证据。超过 100 MiB 或 1000 文件按清单分卷，每卷及单文件符合限额；回导先收齐并核验必需分卷，不半导入。单个不可拆分文件超过上限时明确拒绝并说明证据限制。

## 12. 配额、凭证与维护

需求 §18 的上限作为服务端配置默认值：1—200 题、单文件 10 MiB、每包 100 MiB/1000 文件、每题轨迹文本 10 MiB、执行/评分并发各 1、专家跟踪 300 秒、裁判 120 秒、技术重试 1 次。前端显示实际参数，服务端最终强制执行。

启动前计算最坏调用量并展示；worker 提交前检查调用与时间额度。平台费用未知时仅显示估算预算，不保证精确按费用停止。轮询有独立速率和截止时间。外部在途任务可能继续计费，单独显示。

凭证优先使用操作系统凭证存储，通过 credential_ref 访问；不可用时仅支持进程环境变量引用，错误信息和日志统一脱敏，不能回传前端。平台域名、裁判域名和产物获取来源按连接允许列表限制，不跟随到未授权来源。

归档只改变可见性。删除先计算引用与影响清单，再执行显式确认流程；共享资产有保留引用时拒绝物理删除。标记删除、删除本工具文件与派生物、事务完成及失败恢复分阶段记录，保留无正文最小删除清单。文件访问同时检查对象存续状态，不能借直链读取待删对象。

### 12.1 一致性备份

维护模式使用启动器协调的跨进程写屏障，覆盖 API、worker、导入导出临时文件管理、文件回收和删除恢复任务。所有能改变数据库、文件或引用的普通写操作，在首次文件/数据库写入前取得共享写许可，持有到操作提交或回滚；维护快照阶段取得排他许可。该许可不跨外部网络调用持有。只暂停实验提交或只停止 worker 不算建立备份边界。

1. 请求维护后先拒绝新的普通写操作，返回 503/maintenance；包括发布、导入确认、上传、复核、重评、证据采纳、连接/设置变更、删除和创建导出。只读报告可继续查看。备份控制命令通过启动器执行，不走普通写入口。
2. 停止新任务领取和外部提交；在有界时间内让已进入的本地写入与在途调用收尾，允许后台持久化最后观察。到期仍不明的调用记录外部 ID/幂等键和未知状态，停止 worker 及清理任务。启动器此时禁止自动重启 worker。
3. 等待所有已有共享写许可释放，取得排他许可，再核对未完成的文件写入/删除，修复到可解释的一致状态。若无法完成则备份失败，不产出成功标记。
4. 使用 SQLite Backup API 创建独立数据库快照；不直接只复制 WAL 模式的主 .db 文件，也不将运行中的 WAL/SHM 任意拼接。使用快照中的引用集合固定文件清单，在排他许可仍持有时复制所需对象、删除清单和非秘密运行配置。
5. 校验数据库完整性/外键与全部文件哈希，清单记录 Schema/应用版本、实例谱系、报告修订、未决任务及备份完成状态。写完清单后原子发布备份目录；失败包不作可恢复备份使用。
6. 释放屏障，恢复写入口与 worker。备份副本由用户管理，旧备份不自动清除；凭证不打包，恢复时重新关联。

### 12.2 恢复与副本执行边界

恢复到新目录，首先以离线只读验证模式打开，不启动 worker、不自动轮询或调用外部服务。核对包清单、数据库版本/完整性、引用文件哈希和删除清单；必要迁移仅在恢复副本内、通过检查后执行，保留原备份。恢复演练停留在此模式。

需要接管原实例继续执行时，启动器先确认原目录的 API/worker 已停机，并取得按实例谱系而非数据目录命名的本机互斥锁。正常实例也必须持有该锁；恢复副本不能靠更换目录绕过。无法确认原实例停机，或副本来自另一台仍可能运行的机器时，仅允许验证/浏览，不自动恢复执行，先完成人工接管记录。

接管不生成新的业务幂等键。按 §6 恢复已记录的外部 ID、提交意图、消耗和预算，先查询旧执行；未知任务不盲目重提。需要独立试用副本时，必须创建新实验并重新确认测试环境，不消费克隆的原任务。平台不提供跨机器独占能力时，不能承诺自动阻止另一台机器继续调用，必须在运行说明中列清接管前置条件。

## 13. 实施顺序与验收

| 阶段 | 实施内容 | 出口条件 |
| --- | --- | --- |
| 0 接入核实 | 真实平台契约、能力样例、测试环境、业务政策与裁判服务范围 | 最小能力已核实，缺口逐项记录 |
| 1 基础资产 | 数据迁移、文件快照、评测集、Schema、原子导入和本机边界 | A01、A19、A20、A21；固定包可回导 |
| 2 离线评分 | 证据解析、内置规则、受限裁判、校准、报告及复核 | A02—A09、A12、A15、A17；标记离线预览 |
| 3 对比与维护 | 固定修订对比、消耗、导出、归档删除、备份恢复 | A03、A13、A18、A23 |
| 4 在线闭环 | 一个真实适配器、持久 worker、幂等、取消、恢复和输入隔离 | A10、A11、A14、A16、A22、A24 |
| 5 综合验收 | 全部 A01—A24、真实旧版/新版和性能测量 | 公共与在线验收证据齐全，不以演示替代 |

规则与状态聚合使用需求固定样例验证，特别核对 10 题例的 60%/75%/80%。使用可控故障适配器验证网络超时、提交后崩溃、重复结果、配置漂移与迟到结果；此类测试与真实平台验收区分。输入隔离检查实际序列化请求及允许目录，而不仅检查前端字段。

本版增加以下实现验收，用于覆盖评审指出的数据一致性风险：

| 编号 | 故障/并发场景 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 导出 R1 后产生重评费用、迟到账单或证据补全 | R1 正文/哈希/费用不变，新观察只进入新修订；实时消耗另显 |
| T02 | worker 根据 R0 完成判分，同时用户基于 R0 复核另一题 | 交换提交顺序后当前修订保留两项增量；后台不覆盖人工结论，过期人工请求返回 409 |
| T03 | 平台接受请求后丢失响应，再同键恢复 | 只有一个外部执行归属；传输记录可多条，尝试与费用不重复计数 |
| T04 | 确认原执行未发生后重新执行；或幂等键已过期且状态未知 | 前者追加真正新尝试且保留首次表现，后者阻止自动重提 |
| T05 | 裁判发送后、结果落库前进程崩溃 | 额度仍占用；按能力恢复或有界重试，未知费用可见，实际传输不突破上限 |
| T06 | 备份时并发上传/导入、复核、删除和回收文件 | 维护屏障拒绝或排空写入；恢复后所有引用文件存在且哈希匹配 |
| T07 | 同一备份恢复到另一个目录，原实例仍运行 | 默认离线验证，无外部调用；同谱系锁阻止双实例接管 |
| T08 | 只变目标 Skill、镜像专家 ID 或抓取时间 | 行为字段已核验一致时允许严格比较；目标槽位唯一 |
| T09 | 只变其他 Skill、提示词、模型、权限范围；或必要字段未知 | 返回具体 blocker；不能因移除整个快照或 null 相同而放行 |
| T10 | 同一判分/费用事件重复消费或事务提交时崩溃 | 稳定操作键恢复到同一逻辑结果，无重复修订采纳或费用相加 |

性能使用记录了硬件、版本和数据规模的机器，在 200 题已持久化报告上测首屏和分页 p95，目标 ≤2 秒；不把专家耗时计入 API 查询。对实验状态、报告修订、任务、题目和事件游标建立必要索引，证据正文按需读取。备份恢复必须完成一次固定包演练。

交付清单包括源代码与依赖锁、启动说明、数据库迁移、JSON Schema、验收包、平台脱敏样例、接口文档和验收记录。外部条件未满足时明确记录未通过的在线验收项。

## 14. 尚需外部确认

公司平台的提交、查询、幂等及取消接口；专家实际配置与触发信息；可导出的轨迹、产物和消耗；测试身份和初始状态恢复；真实业务政策与校准资料；允许的裁判服务与资料范围。对应责任与阻塞节点沿用需求 §19。
